## 一、自动化与节奏：多智能体自动派生加上并发上限与嵌套深度默认值

Claude Code 官方版本更新中，两条与"赛博工头"自动化节奏方法论直接相关：

- **v2.1.217（2026-07-21）**：给"并发运行的 subagent 数量"加了默认上限 20（可通过环境变量 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 调整），并把 subagent 默认改为不再派生嵌套 subagent——防止一条指令意外扇出成失控的智能体网络。
- **v2.1.219（2026-07-24）**：把嵌套能力恢复，但设了默认深度上限 3 层。同日，**Claude Opus 5** 发布，成为 Claude Max 套餐的新默认模型（定价 $5/$25 每百万 token）。

对赛博工头"工位/角色/工作流设计"子领域的启发：这组变化实质是官方把"一个任务该配几个工位、能不能无限派生下级"这个赛博工头方法论里的红线问题，做成了平台默认值——先收紧到"不许嵌套"，三天后再放开到"最多三层"，是一次公开可见的"先兜底、再按经验放宽"的护栏调参过程，可直接作为"工位规模上限该怎么定"的参考案例。

来源：[Claude Code Changelog](https://code.claude.com/docs/en/changelog)（v2.1.217、v2.1.219 条目，经 developertoolkit.ai/dev.classmethod.jp 独立信源交叉核实版本号与日期）

## 二、人工闸门与对外守门：OpenAI Presence，把"审批闸门"做成企业级产品

OpenAI 于 **2026-07-22** 发布 **Presence**——一款面向企业的 Agent 部署产品，把治理逻辑做成了产品结构本身：**一个 agent 只做一件事、最小权限访问、显式审批闸门、人工升级路径、上线前先做模拟测试、上线后持续评估**。企业自行设定"agent 可以自主做什么、什么情况需要人批、什么情况必须升级给人"的规则；OpenAI 自家的电话客服部署案例显示 75% 的来电问题可由 agent 自主解决，剩余交由人工处理。上线后，OpenAI 的 Codex agent 会持续审查生产环境里的会话与升级记录、识别薄弱点、提出行为调整建议，但**每一次更新都必须由人工测试并批准后才能上线**。

对赛博工头"人工闸门与对外守门"子领域的启发：这与本业务线一直强调的"人把最后一道关、绝不代按发送键"是同一逻辑，Presence 提供了一个可对标的产品化样本——把"审批闸门"从抽象原则变成了具体的产品结构（角色权限收敛 + 显式审批规则 + 强制人工升级路径 + 变更需人工批准才能生效），可直接用于向客户解释赛博工头"人工闸门"设计的行业参照。

来源：[The Register, 2026-07-22](https://www.theregister.com/ai-and-ml/2026/07/22/openai-tries-the-consulting-path-with-presence-charging-enterprises-boots-on-the-ground-prices-to-deploy-agents/)、[Help Net Security, 2026-07-22](https://www.helpnetsecurity.com/2026/07/22/openai-presence-ai-agent-platform/)（两独立信源交叉核实发布日期与功能细节一致）
